# Dynalektric Commodity Price Intelligence — Public Summary

This repository hosts a **public, non-sensitive** summary page for an internal
Dynalektric tool that compares budgeted aluminium/copper raw-material rates
against today's market price. It exists so the price-trend signal can be
shared with a real URL, without exposing any internal business data.

**Data sources: free and public only.** Aluminium — [NALCO's price circular](https://nalcoindia.com/domestic/current-price/).
Copper — [LME cash settlement via westmetall.com](https://www.westmetall.com/en/markdaten.php?action=table&field=LME_Cu_cash).
No paid subscriptions (Bigmint, Fastmarkets, ICIS, CRU, etc.) are used or
needed for this.

## What's public here vs. what stays private

| | Public (this repo / GitHub Pages) | Private (internal only) |
|---|---|---|
| Item codes | Never | Yes |
| Budgeted rupee prices | Never | Yes |
| Item names/specs | Never | Yes |
| Aggregate signal counts (e.g. "4 critical, 9 review, 5 on track") | Yes | Yes |
| Today's public commodity price (NALCO/LME) | Yes | Yes |
| Full item-by-item table with rates and recommendations | Never | Yes |

The full-detail dashboard (with real item codes and rates) is generated by
`scripts/refresh_commodity_dashboard.py` and lives only in Dynalektric's
private Cowork artifact gallery — it is never committed to this public repo.
This repo only ever holds the small, aggregate `data/public_summary.json`
and the rendered `docs/index.html` built from it.

## How the daily refresh works

`.github/workflows/daily-refresh.yml` runs every day at 03:30 UTC (9:00 AM
IST): it fetches the current NALCO aluminium price and LME copper price
(both free, public), updates `data/public_summary.json`, re-renders
`docs/index.html`, and commits/pushes if anything changed. This part needs
no secrets and no private data — it only ever touches public commodity
prices.

The **item-level aggregate counts** in `public_summary.json` (how many items
are Critical/Review/On track) come from a separate, private process that has
access to the actual Dynalektric item file — that process updates this
repo's `data/public_summary.json` counts fields periodically but never
pushes item codes, names, or rupee figures here.

## Files

- `scripts/refresh_commodity_dashboard.py` — the full-detail analysis engine
  (item selection, premium learning, gap computation). Runs privately against
  the real item file; its output is never committed here.
- `scripts/full_detail_template.html` — HTML shell for the private, full-detail
  dashboard (no sensitive data embedded in the template itself — only filled
  in at render time from the private item file).
- `scripts/public_template.html` / `scripts/render_public.py` — renders the
  public, masked `docs/index.html` from `data/public_summary.json` only.
- `scripts/fetch_public_prices.py` — best-effort daily fetch of NALCO/LME
  prices (regex/PDF-text parsing — see note below on its limits).
- `data/public_summary.json` — the only data file in this repo; intentionally
  aggregate-only, no per-item detail.
- `docs/index.html` — the published GitHub Pages site (enable via
  Settings → Pages → Source: Deploy from a branch → `main` / `/docs`).

## Known limitation

`fetch_public_prices.py` uses regex/PDF-text parsing against NALCO's and
LME's public pages, which is brittle if either source changes its page
layout. This is the free, no-AI-API-cost tier of ingestion. A more resilient
version would use an LLM to read the page/PDF regardless of format drift —
that upgrade is planned but intentionally not wired into this public repo's
free Actions workflow, to avoid introducing any per-run API cost here. It
already exists on the private side, run by an Anthropic Claude scheduled
task under Dynalektric's own Claude/Cowork plan (no additional cost).
